# ВТБ Ко-пилот: Интеллектуальный ассистент и тренажер бэк-офиса

**Спринт №1 (MVP)** — Прототип системы интеллектуальной маршрутизации, строгой регламентной поддержки решений (Strict Grounding) и интерактивного тренажера-песочницы для обучения стажеров бэк-офиса банка ВТБ.

Архитектура системы изначально спроектирована под требования корпоративной безопасности, 152-ФЗ и банковской тайны с изоляцией данных и возможностью развёртывания в закрытом On-Premise контуре банка.

### Принципы безопасности и изоляции данных
1. **Детерминированные локальные гардрейлы**: проверка ответа стажера на запрещенные маркеры (разглашение критериев антифрода, порогов сумм, обхода проверок по регламенту `GEN, п. 5.2`) выполняется на уровне Go-кода до вызова языковой модели. Срабатывание моментально обнуляет оценку и блокирует передачу данных во внешние контуры.
2. **Strict Grounding (строгое регламентное обоснование)**: модель ограничена только переданными фрагментами из `rules.json`. Поле `quote` валидируется и наполняется сервером строго из базы правил, исключая любые галлюцинации.
3. **Автоэскалация при неопределенности**: при нетиповых инцидентах (`COPILOT-07`, исправление даты валютирования задним числом) или отсутствии явных регламентов система автоматически выставляет `escalation_required: true` и направляет задачу руководителю смены.
4. **Абстракция LLM Gateway**: вызовы языковой модели изолированы за интерфейсом `LLMProvider`. В Спринте №1 используется `BaselineAPIAdapter`; архитектура подготовлена к бесшовному переключению во 2-м спринте на локальный On-Prem контур (vLLM / Ollama с открытыми моделями Qwen-2.5 / Vikhr / T-Lite) или защищенный корпоративный шлюз (GigaChat API).

## 🐳 Запуск через Docker Compose (рекомендуется)

Требуется Docker с Compose v2+ (например, Docker Desktop). Go и Node.js на хосте не нужны.

1. Подготовьте `.env` в корне репозитория (образец: `.env.example`):
   ```sh
   cp .env.example .env
   # Укажите LLM_API_KEY (ключ baseline-провайдера Спринта №1)
   ```
2. Запустите сборку и контейнеры:
   ```sh
   docker compose up -d --build --wait
   ```
3. Веб-интерфейс доступен по адресу: **[http://localhost:8080](http://localhost:8080)**.
   * Healthcheck API: `http://localhost:8080/api/health`
   * Список кейсов: `http://localhost:8080/api/v1/cases`
   * База регламентов: `http://localhost:8080/api/v1/rules`

Управление сервисами:
```sh
docker compose ps                # статус и healthcheck сервисов
docker compose logs -f          # просмотр логов
docker compose down             # остановка контейнеров
```

## 🚀 Локальный запуск без Docker (Windows PowerShell / Linux)

### 1. Серверная часть (Go, порт 8000)
API автоматически загружает конфигурацию из ближайшего `.env`:

```powershell
cd backend
go run ./cmd/api
```
* Healthcheck: [http://localhost:8000/](http://localhost:8000/)
* Демо-кейсы: [http://localhost:8000/api/v1/cases](http://localhost:8000/api/v1/cases)

### 2. Клиентская часть (React + Vite, порт 5173)
В отдельном терминале:

```powershell
cd frontend
npm install
npm run dev
```
* Пользовательский интерфейс: **[http://localhost:5173](http://localhost:5173)** (запросы `/api` автоматически проксируются на `:8000`).

## ⚙️ Переменные окружения (.env)

| Переменная | Назначение | Значение по умолчанию |
|---|---|---|
| `LLM_API_KEY` | Ключ доступа к языковой модели (LLM Gateway) | — |
| `GEMINI_API_KEY` | Обратная совместимость для плавного перехода | — |
| `LLM_MODEL` | Модель baseline-адаптера / On-Prem vLLM | `gemini-3.5-flash-lite` |
| `LLM_TIMEOUT` | Таймаут обращений к LLM (1s – 30s) | `25s` |
| `LLM_BASE_URL` | Базовый URL шлюза (On-Prem или внешний API) | `https://generativelanguage.googleapis.com/v1beta` |
| `APP_PORT` | Внешний HTTP-порт в Docker Compose | `8080` |
| `RULES_PATH` | Путь к файлу базы знаний регламентов | `backend/data/rules.json` |

*Примечание: Если ключ `LLM_API_KEY` не задан, система работает в автономном offline-режиме: поиск регламентов и кодовые гардрейлы функционируют в полном объеме, а сложные генерации безопасно эскалируются эксперту.*

## 🎯 Ключевой функционал Спринта №1

### 1. Боевой режим: «Ко-пилот бэк-офиса»
* **Интеллектуальная маршрутизация L1–L3**: определение подразделения и уровня ответственности (L1 — дежурный операционист, L2 — старший операционист / принцип «четырех глаз», L3 — антифрод-аналитик / комплаенс-контроль).
* **Черновик регламентной резолюции**: формирование структурированного решения с пошаговыми действиями, сроками исполнения и проектом ответа клиенту по утвержденным банковским шаблонам (П-1, П-2, П-3).
* **Strict Grounding и Drawer регламентов**: подтверждение каждого действия ссылкой на статью нормативной базы. Клик по карточке источника открывает боковую панель (Drawer) с полным текстом пункта (`GET /api/v1/rules/{id}`).
* **Индикатор уверенности (Confidence Score)**: визуализация степени регламентной обоснованности (высокая 90%, средняя 60%, низкая 20%) с автоэскалацией при выходе за рамки типовых процедур.

### 2. Обучающий режим: «Песочница стажера»
* **Интерактивный тренажер**: решение практических инцидентов бэк-офиса с мгновенным анализом от виртуального наставника.
* **Пошаговые подсказки**: трехуровневая система подсказок, помогающая стажеру последовательно применить нужные статьи регламентов.
* **Кодовые гардрейлы (GEN, п. 5.2)**: блокировка разглашения конфиденциальных алгоритмов безопасности (антифрод, лимиты, обход проверок) с выставлением 0 баллов и выводом яркого предупреждающего бейджа.
* **Детальный чек-лист оценивания**: разбивка оценки (0–10 баллов) по критериям карточки с указанием конкретных упущенных пунктов и эталонного решения.

## 🗺 Дорожная карта: Спринт №2 (Импортозамещение и локальный контур)

1. **Развёртывание On-Prem контура vLLM / Ollama**:
   - Перевод шлюза `backend/internal/llm/` на локальный эндпоинт OpenAI-совместимого API (параметр `LLM_BASE_URL=http://vllm-host:8000/v1`).
   - Использование открытых отечественных моделей и русскоязычных весов:
     * **Qwen-2.5-14B / 32B Instruct** (высокая точность следования строгим JSON-схемам).
     * **Vikhr-7B / T-Lite-Instruct** (оптимизированы для русского языка и деловой переписки).
     * Корпоративный шлюз **GigaChat API (Sber)** по закрытому TLS-каналу банка.
2. **Сайзинг и требования к GPU для On-Premise**:
   - 1× NVIDIA RTX 3090 / 4090 (24GB VRAM) при квантовании AWQ / GPTQ (инференс 14B модели с контекстом 8K токенов).
   - 1× NVIDIA A100 / H100 (80GB VRAM) для высоконагруженного боевого контура (32B–70B моделей, до 60 параллельных сессий операционистов).
3. **Локальный векторный поиск (RAG)**:
   - Внедрение локальных эмбеддингов (`rubert-base-cased` / `bge-m3`) в дополнение к TF-IDF индексу для гибридного семантического поиска.
   - Расширение нормативной базы до 500+ регламентов и инструкций Банка ВТБ.
